# Визуализатор графа зависимостей Rust (Cargo)

Инструмент командной строки для анализа, построения и визуализации графа
транзитивных зависимостей пакетов экосистемы Rust (Cargo).
Разработан в рамках Практической работы №2 (Вариант №30) по дисциплине
«Конфигурационное управление» (РТУ МИРЭА, ИКБО-65-25).

---

## 1. Общее описание программы

Цель разработки — автоматизированный анализ структуры зависимостей пакетов Rust
без использования сторонних библиотек разрешения зависимостей или готовых
пакетных менеджеров.

### Основные возможности:
* **Этап 1 (Конфигурация):** Чтение настроек из файла формата INI, валидация
  всех параметров, вывод параметров в формате `ключ: значение`.
* **Этап 2 (Сбор данных):** Извлечение прямых зависимостей через Crates.io API
  (`https://crates.io/api/v1/crates/{package}/{version}/dependencies`) или
  из локального тестового репозитория.
* **Этап 3 (Построение графа):** Построение графа транзитивных зависимостей
  с помощью рекурсивного алгоритма поиска в глубину (DFS). Корректная обработка
  циклических зависимостей и фильтрация пакетов по заданной подстроке.
* **Этап 4 (Порядок загрузки):** Вычисление обратного топологического порядка
  загрузки (post-order DFS): зависимые библиотеки загружаются раньше,
  а корневой пакет — последним.
* **Этап 5 (Визуализация):** Формирование описания графа на языке Graphviz DOT
  и экспорт в векторный формат SVG (с поддержкой автономного генератора SVG
  без обязательной установки утилиты `dot`).

## 2. Описание функций и настроек

### Структура проекта
* `main.py` — главная точка входа в программу.
* `src/config.py` — загрузка, валидация и форматирование параметров INI.
* `src/collector.py` — извлечение прямых зависимостей (Crates.io / локально).
* `src/graph.py` — рекурсивный DFS для построения транзитивного графа и поиск циклов.
* `src/order.py` — вычисление порядка загрузки пакетов (post-order DFS).
* `src/visualizer.py` — генерация Graphviz DOT и рендеринг SVG.
* `src/cli.py` — интерфейс командной строки, диспетчеризация этапов 1-5.
* `run.sh` — скрипт автоматизации запуска тестов и демонстрации.
* `test_data/` — тестовые графы и структуры зависимостей (`rand`, `regex`, `log`).
* `configs/` — готовые конфигурационные файлы INI.

### Параметры конфигурационного файла INI
Каждый конфигурационный файл содержит секцию `[settings]` со следующими ключами:
1. `package_name` (строка) — имя анализируемого пакета.
2. `repo_url` (строка) — URL API репозитория (например, `https://crates.io/api/v1/crates`)
   или путь к локальному JSON-файлу графа.
3. `test_mode` (булево: `true`/`false`) — режим тестового репозитория.
4. `package_version` (строка) — версия анализируемого пакета (например, `0.8.5`).
5. `output_file` (строка) — путь для сохранения результирующего SVG файла.
6. `filter_substring` (строка) — подстрока для фильтрации/исключения пакетов.

## 3. Команды для сборки, тестирования и запуска

Для работы требуется стандартный интерпретатор Python 3.8+ (без сторонних зависимостей).

### Запуск всех модульных тестов:
```bash
./run.sh test
# или напрямую через unittest:
python3 -m unittest discover tests -v
```

### Запуск полной демонстрации всех этапов:
```bash
./run.sh demo
```

### Запуск конкретного этапа программы:
```bash
python3 main.py --config configs/test_linear.ini --stage 1
python3 main.py --config configs/test_linear.ini --stage 2
python3 main.py --config configs/test_linear.ini --stage 3
python3 main.py --config configs/test_linear.ini --stage 4
python3 main.py --config configs/test_linear.ini --stage 5
python3 main.py --config configs/test_linear.ini --stage all
```

## 5. Сравнение с реальными инструментами пакетного менеджера Cargo

Было проведено сравнение результатов работы визуализатора со штатными
утилитами экосистемы Rust: `cargo tree`, `cargo build` и `cargo-depgraph`.

| Критерий | Наш инструмент | `cargo tree` | `cargo-depgraph` |
| :--- | :--- | :--- | :--- |
| **Формат вывода** | DOT, SVG, текстовый порядок | Текстовое дерево (ASCII) | Graphviz DOT |
| **Алгоритм обхода** | Рекурсивный DFS | DFS с обходом дерева | Полный граф `Cargo.lock` |
| **Циклы** | Помечены красным пунктиром `[цикл]` | Не допускаются Cargo | Отображаются как ребра |
| **Фильтрация** | Подстрока `filter_substring` | Флаги `--depth`, `--edges` | Флаги исключений |
| **Порядок загрузки** | Обратный топологический (post-order)| Порядок компиляции crates | Не вычисляет напрямую |

### Объяснение расхождений:
1. `cargo tree` по умолчанию строит **дерево** зависимостей, в котором общие
   зависимости (например, `rand_core`, используемый и в `rand`, и в `rand_chacha`)
   могут дублироваться в нескольких ветках с пометкой `(*)`. Наш инструмент
   строит единый ориентированный **граф** без дублирования вершин.
2. В реальном Cargo циклические зависимости между нормальными пакетами запрещены
   на уровне компиляции. В нашем инструменте реализована специальная защита
   и явная визуализация циклов (красный пунктир `label="cycle"`), что позволяет
   моделировать и исследовать нестандартные конфигурации.
3. Cargo поддерживает `dev-dependencies` и `build-dependencies`. Наш инструмент
   в режиме сбора данных фокусируется на обязательных рантайм-зависимостях (`normal`),
   исключая тестовые обвязки, не влияющие на выполнение программы.
